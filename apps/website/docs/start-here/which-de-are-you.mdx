# Which DE are you?

"Data engineer" covers several different jobs. Job titles are unreliable, so read the job description for **what you'd build** and **who you'd serve**, then match it to one of these five types. Most roles are a blend; pick the closest one to guide your prep.

## The five types

### Data engineer (generalist)
**Builds:** batch pipelines end to end: ingesting from databases, APIs and files, modeling the warehouse or lakehouse tables, scheduling and monitoring the jobs. The most common "Data Engineer" posting, especially at small and mid-size companies.
**Serves:** analysts, product teams and other engineers.
**Interviews weight:** **SQL**, **Python**, **pipeline design** (idempotency, backfills, incremental loads), data modeling, and one or two tools (usually Spark and Airflow). Broad rather than deep: you're expected to be solid in every round.
**Prep priority:** SQL → pipeline design → Python → modeling → Spark/Airflow deep dive.

### Analytics engineer
**Builds:** the modeled layer analysts and BI tools use: dbt models, metrics definitions, tests, documentation.
**Serves:** analysts, finance, product.
**Interviews weight:** **SQL (heavy)**, **data modeling (heavy)**, metrics and definitions, data quality, stakeholder behavioral. System design is lighter and focused on the warehouse.
**Prep priority:** SQL → modeling → behavioral (metric disputes) → dbt and warehouse deep dive.

### Platform data engineer
**Builds:** the infrastructure everyone else runs on: ingestion frameworks, orchestration, lakehouse storage, compute, access control, cost.
**Serves:** other data engineers and data teams.
**Interviews weight:** **pipeline system design (heavy)**, **Python / coding (heavy)**, tool deep dives (Spark, Airflow, storage formats), reliability and cost. SQL is still tested, usually at a lower bar.
**Prep priority:** system design → Python → tool internals → SQL.

### Streaming data engineer
**Builds:** real-time pipelines: Kafka, Flink or Spark Structured Streaming, CDC, low-latency serving.
**Serves:** product features, fraud, ops dashboards.
**Interviews weight:** **system design with streaming semantics (heavy)**: event time, watermarks, exactly-once, ordering, state. Also coding and Kafka internals.
**Prep priority:** streaming system design → coding → Kafka/Flink deep dive → SQL.

### ML data engineer
**Builds:** data for machine learning: feature pipelines, training datasets, feature stores, data versioning, inference logging.
**Serves:** data scientists and ML engineers.
**Interviews weight:** **point-in-time correctness**, **training/serving skew**, feature pipelines (batch and streaming), data versioning and reproducibility. Plus Python and SQL.
**Prep priority:** modeling for ML (point-in-time joins, leakage) → system design for feature pipelines → Python → SQL.

## Quick way to tell

| If the job description says… | You're probably looking at |
|---|---|
| ETL/ELT, Airflow, Spark, "build and maintain pipelines", a mix of everything | Data engineer (generalist) |
| dbt, Looker/Tableau, "metrics", "single source of truth" | Analytics engineer |
| Spark, Kubernetes, Terraform, "self-serve platform", "cost" | Platform DE |
| Kafka, Flink, "real-time", "sub-second", CDC | Streaming DE |
| feature store, "training data", "model features", MLflow | ML data engineer |
